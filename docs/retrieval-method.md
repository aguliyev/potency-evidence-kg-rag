# Retrieval method and configuration

`retrieve` returns original `source_passage` text with a scoped source/version/passage key, source document metadata, locator, content hash, query cosine, selection mode, hop, via IDs, supporting AGE path, and hub flag. `vector` uses only the bound pgvector index. `graph` combines those vector hits with passages cited by graph entities or by explicitly traversed evidence edges. A candidate appearing in both is marked `both`. No graph summary or AGE property is treated as evidence text.

The retriever embeds the question, checks the active graph/index/embedding binding in a short preflight, then opens one repeatable-read transaction and checks the same binding again. A mismatch aborts retrieval. Vector hits, activated AGE topology, scoped source references, and bound-index passage rows are read in that transaction. The active AGE graph supplies node and edge membership, so raw rows outside the activated projection cannot seed, expand, or contribute passages. Source references that lack a scored passage in the bound index are counted and skipped.

Variant D is the declared graph traversal. It chooses up to eight non-structural, non-hub seed entities that cite the top eight of eight vector hits, ordered by vector rank then entity ID. Each hop follows one evidence relation in either direction (`direction="both"`). Each expanded entity keeps its five highest scoring valid neighbors; the best 50 over all parents form the next frontier. Three hops are allowed. Degree above 20 marks a hub; hubs are not seeds or expansion points unless `expand_hubs` is enabled. One best cited passage per visited entity contributes by default, and a selected edge's source reference may contribute too. The graph candidate limit is 500. Duplicate passage keys are merged and `graph_min_cosine`, when set, drops weaker graph candidates. Diagnostic expansion records give each entity's available/kept relation counts and hub involvement; the trace also records visited entities per hop, skipped provenance counts, and the complete `HybridRetrievalConfig.as_dict()`.

Parallel relations to one neighbor occupy one per-entity beam slot. If `evidence_edges_only=False`, non-evidence relations may appear in the traversal trace, but passages reached through them are ineligible; an evidence relation to the same neighbor takes precedence. Structural document/passage nodes remain excluded regardless of that setting.

The provisional score is `similarity_weight × cosine + hop_bonus[hop] + edge_type_bonus[type]`, using `similarity_weight=1`, hop bonuses `(0.05, 0.05, 0.03, 0.01)` for hops 0–3, and `0.05` for the listed potency relations. The intended downstream graph evidence share is `0.4`; retrieval itself returns candidates and does not spend the answer context budget. All traversal, scoring, and budget values live in `HybridRetrievalConfig`. The required real A/D calibration and complete candidate review are blocked as recorded in [graph-signal-measurement.md](graph-signal-measurement.md). These bonuses were held fixed for the successful P3 pair but are not measurement-calibrated.

## Recorded answer-run configuration

The real answer batch used the implementation frozen at commit `01d0a6e` for retrieval and prompt text. The shared config hash in all twelve successful traces is `4ab6cf693c09b656623c2c024deddb016dfe44c870d0617f3e01eca54c06b029`; the prompt is `answer-prompt-v1`, SHA-256 `3c10d8aee0345061c2de0eef84be1d7cfc18298c3bcb20b252485285aacd7586`. After the first provider attempt failed, the generation adapter was changed to use Instructor markdown-JSON mode for the configured Meta endpoint, which does not accept forced `tool_choice`. The retrieval config and prompt were not changed. The failed attempt's traces are retained at `results/attempt-history/initial-provider-incompatibility/`.

The defaults actually used are eight vector hits; eight seeds drawn from those hits; bidirectional, evidence-edge-only beam traversal; five neighbors per entity; 50 frontier entities per hop; three hops; degree 20 hub cutoff with hub expansion disabled; one best passage per entity; 500 graph candidates; no cosine floor or per-document cap; cosine weight 1; hop bonuses `(0.05, 0.05, 0.03, 0.01)`; a 0.05 bonus for `proposed_in`, `requested_in`, `revised_by`, `concluded_in`, `measures`, and `used_as`; a 40% graph-only evidence share with unused share returned to vector passages; score ordering; last-passage prefix truncation when at least 300 characters fit; 16,000 default evidence characters; one citation repair retry; and whitespace-normalized quote matching after exact matching. These are the defaults of `HybridRetrievalConfig`, not post-result tuning. The complete serialized config is present in every trace.

The only non-default retrieval/answer budget value in the main batch is P3's `max_evidence_chars_per_mode=6000`, declared in `questions.json` and applied to both modes. The CLI was invoked with `--config configs/casgevy-potency.json --output results` and no budget override. It generated graph answers for P1, P2, P4, P5 and P6, plus both modes for P3; five other vector answers are under `results/extra-mode/`. The bound corpus snapshot is `potency-assignment-2026-09-21-v3`; graph and index versions, model identity, sanitized endpoint, usage, and exact evidence are saved in the traces. No run-specific seed, hop, score, graph-share, prompt, or citation-policy override was supplied.

The evidence renderer owns the character budget, including headers and separators. A passage found by vector search owns vector budget even if graph traversal finds it too; only a passage outside the selected vector set can use the graph reserve. All source-derived text sent to generation is in `evidence_text`. The P3 outcome is discussed in [P3 vector versus graph comparison](p3-vector-graph-comparison.md).

The binary candidate rubric and planned A/D verdict ledger live in [graph-signal-measurement.md](graph-signal-measurement.md). The five-query real A/D measurement and complete candidate verdict file were not produced after automatic approval review rejected the earlier request. Consequently variant D and its bonuses remain provisional, and this P3 run is an observed comparison under provisional settings rather than a measurement-calibrated result.
